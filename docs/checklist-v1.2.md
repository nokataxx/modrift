# v1.2 実機検証チェックリスト

v1.2 で実装した機能のうち、**シミュレータ／ヘッドレス Chrome では確認しきれず実機操作が必要な項目**。実機ビルド時に一つずつ潰す用。

> 凡例: `[ ]` = 未検証 / `[x]` = 実機（またはシミュレータで十分な項目）で確認済み / `[-]` = v1.2 では見送り（任意項目）。`→` は補足・所見。

**運用**: 各機能を実装・コミットするタイミングで、その実機検証項目をこのファイルに逐次追記する（鮮度優先）。**v1.2 の開発が一通り終わったら、実機検証に入る前に一度「整理パス」を実施する**:

- 画面/フロー順に並べ替え
- 重複・陳腐化した項目を削除
- 「シミュレータ済み / 実機必須」の区分を再確認
- 横断項目の補完（ダーク・ライト両方 / 日英両方 / iPhone・iPad 両方）

> **v1.2 の現状 (2026-07-07・整理パス実施)**: v1.2 の予定機能は実装完了 — **FR-20**（閲覧＋編集を CodeMirror 一本化）＋依存整理、**FR-15**（全文検索）、**FR-23**（新規ノート）、**FR-22**（リネーム移設）、**iCloud ラベル統一**、**FR-25**（文書スタイルプリセット）、**FR-16**（iPad ネイティブ対応＋大画面最適化）。FR-19（編集履歴）は v1.2 から外し v3以降で検討（改訂16）。本ファイルは実装順に追記してきた項目を画面/フロー順へ並べ替え、FR-25・FR-16 の項目を追加した。

> **なぜ v1.2 は実機確認の比重が高いか（重要）**: FR-20 でレンダリングが **Native (TextKit) → WKWebView 上の CodeMirror** に変わった。WKWebView は `@font-face` の `size-adjust` を無視する等、**ヘッドレス Chrome と実機 WebKit で描画が乖離する**（[[project_ios_webkit_size_adjust_ignored]]）。ヘッドレス確認は開発の当たり付け止まりで、**見た目・フォント・IME は必ず実機で最終確認**する。

> **iPad 確認の注記**: FR-16 で iPad ネイティブ対応（`supportsTablet`）を有効化。**iPad シミュレータで基本レイアウト（中央寄せ・全画面描画）は確認済み**だが、実 iCloud 同期・日本語IME・フォント描画は iPad 実機でも要確認。シミュレータには `data/Library/Mobile Documents/com~apple~CloudDocs/` にファイルをローカル配置すればピッカーの iCloud Drive から開ける（[[project_ipad_native_support]]）。

- [x] **最初の 1 文字を入力した時点でファイルが作成される**（以降の編集は通常どおり自動保存、入力が途切れない＝WebView 再マウントしない）

- [x] **自動命名「無題.md」**、連続作成で「無題-1.md」「無題-2.md」と重複回避される
- [x] **作成後は履歴に載り、リネーム/削除できる**（icloudCopy として FR-22）

      → **経緯 (2026-07-17)**: 当初、検証待ちシミュレータで「＋→入力でアプリが固まる（全ボタン無反応）」現象を確認。真因は「`getContainerDocumentsURL()` はパスを返すが、その後の同期ファイル書き込みがブロックし JS スレッドを固める」こと。一度これを非同期 API（`expo-file-system/legacy`）＋タイムアウトで回避したが、**legacy の `writeAsStringAsync` は NSFileCoordinator を使わず iCloud ubiquity container に書けない**（実機で「not writable」エラー）と判明。そのため**同期の新 API（`File.write`、NSFileCoordinator 経由）に戻した**。この「固まり」は iCloud のパスは返るが書き込みが機能しない**シミュレータ検証待ち状態でのみ**発生し、**実機では再現しない**（上記のとおりサインアウトは即エラー、機内モード/トグルオフはローカルに書けて固まらない）。よって同期 API が実機にとって正解。
- [x] 素早く連続入力しても二重作成されない（作成中ガード）
- [x] 英語 UI では「Untitled.md」で作成される

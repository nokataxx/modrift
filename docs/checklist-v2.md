# v2 実機検証チェックリスト

v2 で実装した機能のうち、**シミュレータ／ヘッドレス Chrome では確認しきれず実機操作が必要な項目**。実機ビルド時に一つずつ潰す用。

> 凡例: `[ ]` = 未検証 / `[x]` = 実機（またはシミュレータで十分な項目）で確認済み / `[-]` = v2 では見送り（任意項目）。`→` は補足・所見。

**運用**: 各機能を実装・コミットするタイミングで、その実機検証項目をこのファイルに逐次追記する（鮮度優先）。**v2 の開発が一通り終わったら、実機検証に入る前に一度「整理パス」を実施する**:
- 画面/フロー順に並べ替え
- 重複・陳腐化した項目を削除
- 「シミュレータ済み / 実機必須」の区分を再確認
- 横断項目の補完（ダーク・ライト両方 / 日英両方 / iPhone・iPad 両方）

> **v2 の現状 (2026-07-07・整理パス実施)**: v2 の予定機能は実装完了 — **FR-20**（閲覧＋編集を CodeMirror 一本化）＋依存整理、**FR-15**（全文検索）、**FR-23**（新規ノート）、**FR-22**（リネーム移設）、**iCloud ラベル統一**、**FR-25**（文書スタイルプリセット）、**FR-16**（iPad ネイティブ対応＋大画面最適化）。FR-19（編集履歴）は v2 から外し v4以降で検討（改訂16）。本ファイルは実装順に追記してきた項目を画面/フロー順へ並べ替え、FR-25・FR-16 の項目を追加した。

> **なぜ v2 は実機確認の比重が高いか（重要）**: FR-20 でレンダリングが **Native (TextKit) → WKWebView 上の CodeMirror** に変わった。WKWebView は `@font-face` の `size-adjust` を無視する等、**ヘッドレス Chrome と実機 WebKit で描画が乖離する**（[[project_ios_webkit_size_adjust_ignored]]）。ヘッドレス確認は開発の当たり付け止まりで、**見た目・フォント・IME は必ず実機で最終確認**する。

> **iPad 確認の注記**: FR-16 で iPad ネイティブ対応（`supportsTablet`）を有効化。**iPad シミュレータで基本レイアウト（中央寄せ・全画面描画）は確認済み**だが、実 iCloud 同期・日本語IME・フォント描画は iPad 実機でも要確認。シミュレータには `data/Library/Mobile Documents/com~apple~CloudDocs/` にファイルをローカル配置すればピッカーの iCloud Drive から開ける（[[project_ipad_native_support]]）。

## リネームの導線移設 (FR-22・改訂20)

> リネームは履歴スワイプ廃止 → viewer ヘッダのファイル名長押しへ。スワイプは「リストから削除」のみ。削除は履歴行の長押し ActionSheet のまま。

- [ ] **履歴のスワイプに「名前を変更」が出ない**（全行「リストから削除」だけ）
- [ ] **Modrift コピー/新規ノートを開き、ヘッダのファイル名を長押し → リネームのプロンプトが出る**
- [ ] リネーム後、ヘッダのタイトルが新名に変わり、そのまま編集を続けても保存先が正しい（＝入力が途切れない・新 uri に保存）
- [ ] リネーム後、ホームに戻ると履歴のファイル名も更新されている

- [ ] **iCloud Drive 原本・外部クラウド・Open In のファイルではファイル名長押ししてもリネームできない**（icloudCopy 以外は無反応）
- [ ] ファイル削除は従来どおり履歴行の長押し ActionSheet から行える（スワイプには無い）

- [ ] **閲覧モードは記法マーカーを見せず整形表示、編集モードはカーソル行だけ生の記法を露出する**（Obsidian 風ライブプレビュー）
- [ ] **編集 ⇄ プレビュー トグルで内容・スクロール位置・undo 履歴が保たれる**（リロードによるチラつき・先頭戻りが無い）
- [ ] **in-place 編集可（iCloud/ローカル）はヘッダーに編集ボタン、非 in-place（Google Drive 等）は編集ボタンでなく iCloud コピー作成ボタンが出る**

## ビューア: Markdown レンダリング（実機 WebKit 必須）

> 各要素が実機のライト・ダーク両方で、見た目が旧 Native レンダラの体裁に沿って崩れず出るか。

- [ ] **見出し H1〜H6** — サイズ・色階層（既定=ネイビー系）、太字化しない方針
- [ ] **太字・斜体・打ち消し線（GFM）・inline code**
- [ ] **箇条書き / 順序付きリスト / ネストリスト** — 行間 base×1.65、インデントが実機で自然か
- [ ] **引用 / ネスト引用** — 左アクセントバー（accent 色）、角丸
- [ ] **水平線（`---`）がライト・ダーク両方で見える**（極薄で埋もれない）
- [ ] **コードブロックがシンタックスハイライト付きで出る** — 対応言語は色分け、未対応言語は等幅＋単色フォールバック、角丸カード
- [ ] **テーブル（GFM）** — 罫線グリッド、ヘッダ網掛け無し、横スクロール可
- [ ] **画像** — https は inline 表示、ローカル/相対パスは `[画像: ファイル名]` プレースホルダ（i18n）
- [ ] **CJK/Latin 混在の字面が揃う** — 和文ヒラギノ＋英 SF、`palt`、CJK 隣接スペース圧縮。size-adjust を使わず inline font-size span で調和（実機と Chrome で差が出る箇所）
- [ ] **文字サイズ設定（小/中/大）で本文・見出し・コードが一体でスケール**する

## ビューア: Undo / Redo（CodeMirror history）

> undo/redo は自前スタックでなく CM 内蔵 history に委譲。編集モード時のみヘッダーにアイコン。

- [ ] **編集モードのヘッダーに undo/redo が出る**（プレビュー時は出ない。スタックが空なら淡色＝無効）
- [ ] **連続入力 → undo 1回でその塊がまとめて戻る**（1文字ずつでない）

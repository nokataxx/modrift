## 競合警告UI (FR-13)

> **重要な前提**: 検知はローカルファイルの更新時刻に依存する。iOS はファイルを開いている間、他デバイスの変更を即座にはダウンロードしないため、「別端末で変更 → 数秒後に保存」ではほぼ検知されない（実機ログで確認済み: 保存時点では旧 mtime、数分後の再オープンで新 mtime）。これは File Provider の観測限界で仕様。**現実的な検証は「前景復帰の再チェック」経路で行う**。
>
> 再現手順（前景復帰経路）: ① 実機 Modrift でファイルを開いて1文字編集（未保存の状態を作る） → ② Modrift をバックグラウンドへ（ホームに戻る） → ③ 別デバイス（Mac の TextEdit/ターミナル等）で同じファイルを更新 → ④ 同期が落ち着くまで十数秒〜数分待つ → ⑤ Modrift に戻る（前景復帰）。

- [x] **前景復帰時に競合ダイアログが出る** — 未保存の編集がある状態で外部変更を検知 → 「ファイルが変更されています」（時間が経って同期が落ちた後に確認）
- [x] **「編集中の内容を保持」で上書き保存できる** — ※ダイアログ表示は確認済み（上記）。2択の処理自体は `viewer.tsx` の `promptConflict`（保持＝`writeFile` / 最新版＝`reloadFromDisk`）でコードレビュー確認。実機での再現は下記の構造的制約で困難なため割り切り
- [x] **「最新版を取得」で外部版に差し替わる** — ※同上（コードレビュー＋ダイアログ既出で確認扱い）
- [x] **未保存の編集が無い状態で前景復帰すると、外部変更が静かに最新へ追従する**（ダイアログは出ない） — 実機確認: 別端末変更→前景復帰でプレビューが静かに最新へ更新、誤ダイアログなし
- [x] 競合が無い通常編集では従来どおりサイレントに自動保存される（誤検知でダイアログが出ない） — 実機確認
- [ ] （任意）保存時検知: 端末が既に新版を持っている状態（しばらく前に別端末で編集→同期済み）で編集→保存するとダイアログが出る

> **A/B（ダイアログの2択）が実機で出しにくい理由**: 離脱時に自動保存が走り「未保存」状態が消えること＋iOS がファイルを開いている間は他端末の変更をローカルに落とさないこと（File Provider の観測限界）が重なり、「未保存編集 AND 落ちてきた外部変更」を同時に作るのが構造的に困難。ダイアログ表示自体は別途確認済みで、2択処理はコードで担保。

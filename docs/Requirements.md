# Modrift 要件定義書 (v3〜)

- **作成日**: 2026-10-30
- **想定読者**: 開発者本人と、相談相手の Claude
- **位置づけ**: v3 で仕様を白紙から見直した。**本書が唯一の要件定義**で、v1〜v2 (編集・ホームフォルダ・有償 Pro) の要件定義書は削除した (必要なら git のタグ `v2.0.0` から参照できる)

## 1. 概要

Modrift は、**Files App では生テキストのまま表示されてしまうファイルを、整形して読みやすく表示する iPhone / iPad 向けの無料ビューア**。

- **閲覧専用**。編集機能は持たない
- **どこのファイルでも同じ扱い**。iCloud Drive・Google Drive・Dropbox・メール添付のどれでも、開ければ読める
- **全機能無料**。課金・アカウント・広告なし

**名前の由来**: **Mo** (Mobile) + **drift** (漂う、流れる)。モバイルで、どこにあるファイルにも軽やかに行き来できる。

## 2. 想定利用者と使う場面

**利用者: 開発者・技術系の人** (v3 の範囲)。より広い層 (メモや文書を扱う一般の人) へ広げるかは、別途議論してバージョンアップで扱う。

**場面の例**:

- 移動中に、GitHub リポジトリの README や設計メモ (.md) を iPhone で読む
- Slack やメールで届いた設定ファイル (JSON / YAML) やスクリプトを、色付きで確認する
- クラウドに置いたコードを、PC を開かずにちょっと読む

## 3. Files App との関係

iOS の Files App は Quick Look で **PDF・Office 文書・画像をきれいに表示できる**。Modrift はそこで勝負しない。

Quick Look が苦手なのは**テキスト系のファイル**で、Markdown は記法がそのまま見え、JSON やコードは色付けも整形もされない。**Modrift はこの隙間だけを埋める**。Files App とは競合せず補完関係にあり、ファイル管理 (移動・リネーム・削除) も Files App に任せる。

## 4. 対応形式

| 形式 | 拡張子 | 表示 | リリース |
|---|---|---|---|
| Markdown | .md / .markdown | 整形表示 (GFM: 表・タスクリスト・取り消し線)。コードブロックはハイライト | v3.0 |
| プレーンテキスト | .txt / .text | そのまま表示 | v3.0 |
| 構造化データ | .json / .yaml / .yml / .toml / .xml | シンタックスハイライト・折りたたみ | v3.0 |
| ソースコード | 主要言語 (下記) | シンタックスハイライト | v3.0 |
| 表形式 | .csv / .tsv | 表として表示 | v3.1 (予定) |
| ノートブック | .ipynb | セル・Markdown・出力を整形表示 | v3.2 (予定) |

**v3.0 で対応するコードの言語** (案): JavaScript / TypeScript、Python、Swift、Shell、Go、Rust、HTML、CSS、SQL。CodeMirror の言語パックを足すたびにバンドルが大きくなるので、**入れるのは利用者が多い言語に絞る**。最終的な一覧は実装時に決める。

**対応しない形式**: PDF・Word・Excel・画像 (Quick Look が得意で、Modrift が勝てる余地がない)。

## 5. 機能要件

### FR-01: ファイルを開く

3つの入口のどれからでも、同じビューア画面に到達する。

- **経路A: アプリ内のファイルピッカー** — ホームの「ファイルを開く」から、iOS のシステムピッカーで選ぶ
- **経路B: Open In** — Files App などで対象ファイルを開き、「Modrift で開く」を選ぶ。`CFBundleDocumentTypes` で第4章の形式を宣言する (`LSHandlerRank: Alternate`)
- **経路C: 共有シート** — 他のアプリの「共有」から Modrift を選ぶ (Share Extension)

開けないときは、黒画面や無限ローディングにせずエラーを表示し、再試行できるようにする。

### FR-02: Markdown の表示

- CodeMirror 6 を WebView 上で**読み取り専用**で動かして描画する (v1〜v2 の資産)
- 記法は隠して整形表示する。GFM の表・タスクリスト・取り消し線、コードブロックのハイライトに対応
- リンクはタップで開く
- 画像は **HTTPS の画像のみ表示**し、相対パスの画像はファイル名のプレースホルダにする (単一ファイルにしかアクセス権がないため)
- タスクリストのチェックボックスは見た目のみ。タップしても切り替わらない (切り替えはファイルの書き換え＝編集になる)

### FR-03: 構造化データ・コードの表示

- 拡張子から言語を判定してハイライトする
- 折りたたみ (JSON / YAML などのブロック単位)
- 長い行は折り返す。行番号を表示する
- 改行のない JSON (圧縮された JSON) は読めないので、**整形表示 (インデント付け) を切り替えられる**ようにする。整形は表示だけで、ファイルは変更しない

### FR-04: 最近見たファイル

- ホームは「最近見たファイル」の一覧と「ファイルを開く」ボタンで構成する
- タップで開き直せる。Security-Scoped Bookmark を保存して、アプリを再起動しても開けるようにする
- **記録するのは経路A (ピッカー) で開いたものだけ**。経路B・C で届くのは使い捨てのコピーや、再起動後に開き直せない URI なので記録しない (v1〜v2 の実機検証で確定)
- 長押しで履歴から削除できる

### FR-05: 文書内検索

開いているファイルの中を検索し、該当箇所へスクロールしてハイライトする。

### FR-06: 表示設定

- ダーク / ライト (システムに追従、または固定)
- フォントサイズ
- 配色スタイル (プリセットから選択)
- アプリアイコンの切り替え
- 表示言語は日本語・英語。端末の言語に従う

### FR-07: 画面の向きと iPad

- iPhone はビューアのみ横向きを許可し、それ以外は縦固定
- iPad は全画面で4方向に対応する。本文は読みやすい幅 (42em) で中央に寄せる

## 6. 意図的に実装しないもの

- **編集** (Markdown・コードとも)。書き戻しの可否がプロバイダで異なるという iOS の制約が、v1〜v2 の複雑さの原因だったため
- **ファイル管理** (新規作成・リネーム・削除・移動・複製) — Files App に任せる
- **アプリ専用のフォルダ (旧ホームフォルダ)**、クラウド間のコピー
- **PDF・Word・Excel・画像の閲覧**
- **課金・アカウント・広告**
- フォルダ単位の閲覧、内部リンク `[[...]]`、ローカル画像の表示 — iOS がサードパーティのプロバイダのフォルダ参照を塞いでいるため
- 複数ファイルの横断検索 (ディスク全体の索引は作れない)

## 7. 技術上の制約 (v1〜v2 で実機検証済み。v3 でもそのまま有効)

- **Expo (React Native) + TypeScript、expo-router**。New Architecture が前提で、Expo Go では動かないため **Expo Dev Client が必須**
- **ファイルの読み込みは協調読み込みで行う**: `File.text()` ではなく自前のネイティブモジュール `FileBookmarkModule.readFileCoordinated(uri)` を使う。素の読み込みは、ダウンロードされていない Google Drive 等のファイルで「no such file」やハングになる
- **ピッカーは `copyToCacheDirectory: false` に固定**。`true` にすると、ダウンロードされていないファイルでコピー自体が失敗する
- **WKWebView は `@font-face` の `size-adjust` を無視する**。和文と欧文のサイズ調整は inline の `font-size` で行う。ヘッドレス Chrome の見た目は実機と違うので、**表示の確認は実機で行う**
- **スクロールの慣性**: CodeMirror に `height: 100%` を当てない、WebView に `decelerationRate="normal"` を明示する。どちらかを外すと、長文のフリックが途中で止まる
- **ピッカーの開始位置やタブは公開 API で変えられない**。システムの既定のまま使う

## 8. v2 からの移行

v3.0 は、同じ Bundle ID (`com.modrift.app`) の新バージョンとして出す。名前とストアのページは引き継ぐが、**v2 までの利用者はほぼいないため、既存ユーザーへの移行配慮はしない**。

**削るもの**:

- 編集一式 (編集モード、自動保存、外部変更の検知、undo/redo、編集ツールバー、新規作成)
- ホームフォルダ一式 (マイファイル、iCloud ⇄ iPhone 内の切替、ホームにコピー、リネーム・削除・複製・選択モード)
- **iCloud の利用そのもの**: iCloud コンテナの entitlement (`iCloud.com.modrift.app`) と `NSUbiquitousContainers` の宣言。`UIFileSharingEnabled` (アプリの書類フォルダを Files App に見せる設定) も不要になる。旧ホームフォルダのファイルは利用者の iCloud アカウントに残るが、Files App からは見えなくなる可能性がある
- 課金一式 (RevenueCat、ペイウォール、購入の復元)
- PDF・Word・Excel・画像のビューア、mammoth・SheetJS のバンドル、対応する UTI 宣言
- v1〜v2 の要件定義・チェックリスト・ADR など、v3 で使わないドキュメント

**`LSSupportsOpeningDocumentsInPlace` は実装時に判断する**: Open In で元のファイルを直接受け取るか、コピーを受け取るかが変わる設定。外すと協調読み込み (第7章) の前提が変わるので、実機で経路B の動作を確かめてから決める。

**リリースノートで伝えること**: 閲覧専用のアプリになり、編集機能がなくなったこと。
